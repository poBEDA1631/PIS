# Таблиця простежуваності вимог (Requirements Traceability Matrix)

| ID вимоги | Опис вимоги | Критерій прийняття | BDD-сценарій |
| :--- | :--- | :--- | :--- |
| **REQ-F-001** | Пошук та фільтрація книг у каталозі | Частковий збіг у назві/авторі; пошук за ISBN; фільтрація за жанрами | **Сценарій 1:** Пошук книги за частковою назвою |
| **REQ-F-002** | Відображення картки книги та `TitleAvailability` | Агрегація станів: `AVAILABLE` (є хоч 1 вільна), `UNAVAILABLE` (всі видані/в ремонті), `OUT_OF_STOCK` (всі `LOST`) | **Сценарій 1:** Відображення агрегованого стану книги |
| **REQ-F-003** | Управління статусом примірника (`IN_REPAIR`) | Дозволені переходи з `AVAILABLE`/`BORROWED` у `IN_REPAIR`; заборона бронювання (`RESERVED`) примірника в ремонті | **Сценарій 2:** Переведення примірника в статус `IN_REPAIR` та блокування бронювання |
| **REQ-F-004** | Архівування книги (`isArchived`) | Встановлення `isArchived = true` лише якщо всі примірники `LOST`; приховування з публічного пошуку читачів | **Сценарій 3:** Читач шукає книгу, яку було заархівовано бібліотекарем |
| **REQ-NF-001** | Продуктивність пошуку | Час відгуку пошукового запиту $< 500$ мс | Перевіряється автоматизованими інтеграційними тестами продуктивності |
| **REQ-NF-002** | Цілісність даних та валідація статусів | Блокування недозволених перехідних станів на рівні доменної моделі | **Сценарій 2:** Валідація відхилення забороненого статусу `RESERVED` для `IN_REPAIR` |
| **REQ-NF-003** | Обмеження доступу та безпека | Операції зміни статусів та архівування доступні виключно ролі Бібліотекар | Перевіряється тестами модулів авторизації та прав доступу |
